# Ход работ

## Этап 1. Каркас — готово (3 октября)

Сделано:
- бэкенд: FastAPI, настройки через `.env`, async SQLAlchemy, все сущности раздела 5 и миграция `0001`, `/api/health`, OpenAPI на `/api/docs`;
- `services/state_machine.py`: полная таблица переходов, ошибки 409/403/422 на русском, журнал `order_events`, живые события; тесты на все разрешённые и ключевые запрещённые переходы;
- вход логин + ПИН, JWT, `require_role`, блокировка после 5 неверных попыток;
- WebSocket `/ws`: подписка по роли из токена, адресные события исполнителю, LISTEN/NOTIFY между процессами;
- фронтенд: Vite + React + TS strict + Tailwind 4 + PWA, маршруты `/w /m /panel /boss /admin /dev/ui /demo` с защитой по ролям, вход, `useLiveEvents`, i18n ru/kk;
- инфраструктура: `docker-compose.yml` (db, backend, scheduler, bot, frontend на Caddy), `infra/Caddyfile` с автоматическим HTTPS, `Makefile`, `tasks.ps1` для Windows, GitHub Actions (ruff, mypy, pytest на PostgreSQL, eslint, tsc, сборка);
- базовые учётные записи (`python -m seed`): admin/0000, boss/1111, master1/2222, worker1/3333.

Проверено: 95 тестов бэкенда, ruff, mypy, eslint, tsc, сборка; миграция вверх и вниз; локальный запуск на SQLite — вход мастера, переход в панель, WebSocket «На связи», закрытый чужой раздел.

Не проверено: `docker compose up` — на машине разработки пока нет Docker.

## Этап 2a. API нарядов — готово (3 октября)

Сделано:
- справочники для всех ролей (`/api/sections`, `/equipment`, `/fault-codes` с нормативами, `/materials`, `/brigades`), последнее оборудование мастера, поиск по QR;
- администрирование: CRUD и импорт CSV для участков, оборудования, бригад, шифров, материалов, сотрудников (`/api/admin/{kind}`);
- выдача наряда: автономер, участок из оборудования, тип и срок из приоритета, уведомление исполнителю (или всей бригаде);
- статусы людей смены (`/api/people/shift`) и счётчики смены (`/api/shift/summary`);
- действия исполнителя и мастера (`/api/orders/{id}/actions/{action}`), форма закрытия (`/complete`), переназначение, смена приоритета, изменение оценки ИИ;
- фото: до 5 на «до» и «после», превью, время из EXIF, pHash;
- история по наряду (в карточке) и по оборудованию;
- миграция `0002`: признак «оборудование остановлено».

Схема БД: добавлено поле `orders.equipment_stopped` (миграция 0002).

Проверено: 119 тестов, ruff, mypy.

## Этап 2c. Генератор данных — готово (3 октября)

Сделано:
- `python -m seed` (`make seed`): справочники в объёме ТЗ, 550+ нарядов за 3 месяца, журнал, оценки ИИ, списания, простои; детерминированно (seed=42), около 4 секунд;
- пять закономерностей с настраиваемой силой (`seed/history.py`, `PatternConfig`);
- демо-сцена текущей смены (`python -m seed --scene-only`): 2 свободных слесаря, электрик и сварщик в работе, слесарь с очередью из 2 нарядов, отклонённый наряд, наряд на проверке ИИ, отгул;
- `python -m seed.check` (`make seed-check`): статистика и подтверждение закономерностей цифрами;
- правила проверки закрытия (`verification/rules.py`), агрегатор вердикта, тематическое сравнение работ с проблемой, шаблонные отчёты исполнителю и мастеру — оценки в истории ставит тот же код, что и в живой проверке.

Схема БД: таблица `app_state` (миграция 0003) — граница истории для сброса демо-сцены.

Проверено: 125 тестов (в том числе: все закономерности на месте; ослабленная закономерность не проходит проверку; сброс сцены быстрее 2 с и не трогает историю).
