## 1. Отправить тег сдачи на GitHub

Тег `v1.0-submission` уже стоит на последнем коммите у вас на компьютере, но на GitHub он пока указывает на старый. Откройте терминал в папке проекта (`NaryadAI`) и выполните:

```bash
git push -f origin v1.0-submission
```

Проверка: на странице https://github.com/zhenisoffical1/NARYAD_AI нажмите на переключатель веток → вкладка **Tags** → `v1.0-submission` должен вести на коммит «feat: ассистент мастера…».

**После любых новых правок до 8 октября** повторяйте:

```bash
git tag -f v1.0-submission
```

```bash
git push origin main
```


## 2. Проверить автотесты на GitHub

1. Откройте https://github.com/zhenisoffical1/NARYAD_AI/actions.
2. Последний запуск **CI** должен быть зелёным (галочка). В нём: линтеры, проверка типов, тесты бэкенда на PostgreSQL, точность ИИ, сборка фронтенда.
3. Если красный — откройте его, нажмите на упавший шаг, скопируйте текст ошибки и пришлите мне.

Зелёная галочка в репозитории — сигнал жюри, что код проверяется автоматически. Если вкладка Actions выключена: **Settings → Actions → General → Allow all actions** → Save.

## 3. Создать Telegram-бота

Бот работает без публичного адреса (сам опрашивает Telegram), поэтому его можно создать сразу.

1. В Telegram найдите **@BotFather** (с синей галочкой) и нажмите **Start**.
2. Отправьте `/newbot`.
3. Имя бота (видно в чатах): например `НарядAI — Костанайские Минералы`.
4. Логин бота (латиницей, должен кончаться на `bot`): например `naryadai_km_bot`. Если занят — добавьте цифры.
5. BotFather пришлёт **токен** вида `8123456789:AAH...` — это пароль от бота, **никому не показывайте и не выкладывайте в репозиторий**.
6. Оформление (по желанию, но красиво на защите):
   - `/setuserpic` → выберите бота → отправьте эмблему (квадратная картинка; можно взять `frontend/public/brand/km-logo.png`);
   - `/setdescription` → «Наряды смены: новые наряды с кнопками „Принять“ и „В очередь“, напоминания о сроках, аварийные вызовы.»
   - `/setcommands` → вставьте:
     ```
     start - Подключить уведомления
     stop - Отключить уведомления
     ```
7. Запишите два значения — они понадобятся на шаге 8:
   - `TELEGRAM_BOT_TOKEN` = токен;
   - `TELEGRAM_BOT_USERNAME` = логин бота **без @** (например `naryadai_km_bot`).

## 4. Ключ Claude и замер точности ИИ

Без ключа система полностью работает на правилах (точность 93%). С ключом включаются: проверка «работы соответствуют проблеме» моделью, **сравнение фото «до/после»** (пункт ТЗ 6.3), выводы аналитики, сводки смены и разбор вопросов ассистенту. Для защиты ключ стоит иметь — «качество ИИ» весит 25 баллов из 100.

1. Откройте https://console.anthropic.com и зарегистрируйтесь (почта или Google).
2. **Billing** → пополните баланс (банковская карта). Для хакатона хватит минимальной суммы: одна проверка наряда стоит доли цента, весь замер на 30 случаях — порядка доллара.
3. **API Keys** → **Create Key** → название `naryadai` → скопируйте ключ `sk-ant-...` (показывается один раз).
4. Вставьте ключ в файл `.env` в корне проекта у себя на компьютере:
   ```
   ANTHROPIC_API_KEY=sk-ant-...
   ```
   Файл `.env` не попадает в git (он в `.gitignore`) — ключ не утечёт.
5. Замер точности на вашем компьютере (Windows, PowerShell, в папке проекта):
   ```powershell
   .\tasks.ps1 ai-eval
   ```
   Или на сервере после шага 8:
   ```bash
   make ai-eval
   ```
6. В конце будет строка с точностью и временем проверки, а результат сохранится в `backend/tests/ai_eval/results.json`. **Пришлите мне вывод** — я впишу цифру в README и презентацию (строка «С ANTHROPIC_API_KEY» в таблице качества ИИ).
7. Если в консоли Anthropic стоит лимит расходов — **Limits** → поставьте, например, 20 $/месяц, чтобы не было сюрпризов.

## 5. Арендовать сервер

Нужен облачный сервер (VPS) с публичным IP-адресом.

**Параметры:** Ubuntu 24.04 LTS, **2 ядра, 4 ГБ памяти**, 40 ГБ диска. Меньше 4 ГБ памяти — сборка может не пройти.

**Где взять** (любой вариант, оплата картой):
- в Казахстане: PS.kz, Hoster.kz — данные остаются в стране, это плюс для «применимости на предприятии»;
- за рубежом: Hetzner, DigitalOcean, Timeweb Cloud.

При создании сервера:
1. Образ — **Ubuntu 24.04**.
2. Доступ — по паролю root (проще) или SSH-ключу.
3. После создания запишите **IP-адрес** (например `185.22.33.44`) и пароль.

## 6. Получить адрес сайта (домен)

HTTPS обязателен: без него телефон не даст камеру, микрофон и установку приложения. Сертификат система выпустит сама, нужен только домен, который указывает на IP сервера.

**Вариант А — бесплатно, 5 минут (DuckDNS):**
1. Откройте https://www.duckdns.org, войдите через Google или GitHub.
2. В поле **sub domain** введите, например, `naryadai` → **add domain**.
3. В строке домена в поле **current ip** впишите IP сервера → **update ip**.
4. Ваш адрес: `naryadai.duckdns.org`.

**Вариант Б — свой домен** (солиднее на защите, например `naryadai.kz` или `naryad-ai.com`):
1. Купите домен у регистратора (PS.kz, Hoster.kz, Namecheap, REG.RU). Учтите: домены `.kz` по правилам должны работать на серверах в Казахстане.
2. В настройках DNS домена создайте запись: тип **A**, имя `@` (или поддомен, например `naryad`), значение — **IP сервера**.
3. Подождите 5–30 минут. Проверка в PowerShell: `nslookup naryadai.kz` — должен показать IP сервера.

Дальше в инструкции адрес обозначен как **`ВАШ_ДОМЕН`**.

## 7. Подготовить сервер

1. Подключитесь (Windows → PowerShell):
   ```powershell
   ssh root@IP_СЕРВЕРА
   ```
   На вопрос `Are you sure...` ответьте `yes`, введите пароль (символы не отображаются — это нормально).
2. Обновите систему:
   ```bash
   apt update && apt upgrade -y
   ```
3. Установите Docker (официальный скрипт):
   ```bash
   curl -fsSL https://get.docker.com | sh
   ```
4. Проверьте:
   ```bash
   docker compose version
   ```
5. Откройте порты (SSH, HTTP, HTTPS):
   ```bash
   ufw allow 22 && ufw allow 80 && ufw allow 443 && ufw --force enable
   ```
   В панели провайдера тоже проверьте, что «файрвол / группа безопасности» пропускает **80** и **443**.
6. Установите git и make:
   ```bash
   apt install -y git make
   ```

## 8. Запустить систему

1. Скачайте код:
   ```bash
   cd /opt && git clone https://github.com/zhenisoffical1/NARYAD_AI.git naryadai && cd naryadai
   ```
   Если репозиторий приватный, git спросит логин и пароль: логин — ваш GitHub, вместо пароля — токен (**GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate**, галочка `repo`).
2. Создайте настройки:
   ```bash
   cp .env.example .env
   ```
3. Сгенерируйте секрет для входа:
   ```bash
   openssl rand -hex 32
   ```
   Скопируйте получившуюся строку.
4. Откройте настройки в редакторе:
   ```bash
   nano .env
   ```
   Поменяйте строки (остальное не трогайте):
   ```
   JWT_SECRET=строка_из_пункта_3
   DEMO_MODE=true
   ANTHROPIC_API_KEY=sk-ant-...
   TELEGRAM_BOT_TOKEN=8123456789:AAH...
   TELEGRAM_BOT_USERNAME=naryadai_km_bot
   PUBLIC_URL=https://ВАШ_ДОМЕН
   SITE_ADDRESS=ВАШ_ДОМЕН
   ```
   - `DEMO_MODE=true` — нужен для защиты (пульт `/demo`, сброс сцены, вход по QR). После хакатона ставьте `false`.
   - `SITE_ADDRESS` — **без** `https://`, просто `naryadai.duckdns.org`.
   - Сохранить в nano: **Ctrl+O**, **Enter**, выйти: **Ctrl+X**.
5. Соберите и запустите (первый раз 10–20 минут):
   ```bash
   docker compose up -d --build
   ```
6. Проверьте, что все 5 сервисов работают (`db`, `backend`, `scheduler`, `bot`, `frontend` — статус `Up`, у backend и db — `healthy`):
   ```bash
   docker compose ps
   ```
7. Заполните базу тестовыми данными (справочники, 3 месяца истории, демо-смена):
   ```bash
   make seed
   ```
   ⚠ `make seed` **стирает всю базу** и создаёт заново. Для сброса только демо-смены перед показом используйте кнопку на пульте `/demo` или `make scene`.
8. Логи, если что-то не так:
   ```bash
   docker compose logs -f --tail=100
   ```
   Выход из логов — **Ctrl+C** (система продолжит работать).

## 11. APK (по желанию)

ТЗ принимает «APK **или** ссылку на PWA» — ссылки `https://ВАШ_ДОМЕН` достаточно. Если хотите ещё и APK-файл:

1. Откройте https://www.pwabuilder.com, вставьте `https://ВАШ_ДОМЕН` → **Start**.
2. Дождитесь оценки → **Package for stores** → **Android** → **Generate Package**.
3. Скачается архив: внутри `.apk` (установить на телефон) и `assetlinks.json` (+ ключ подписи — **сохраните архив целиком**, он нужен для обновлений).
4. **Пришлите мне `assetlinks.json`** — я положу его на сайт (`/.well-known/assetlinks.json`), тогда APK будет открываться во весь экран без адресной строки.
5. Установка APK на телефон: перешлите файл себе (Telegram / Google Диск), откройте, разрешите «установку из неизвестных источников».

## 12. Видео демо до 3 минут

Нужно на случай проблем со связью на защите. Снимайте **на сервере** (не локально), с двумя телефонами и панелью.

**Чем записать:**
- экран компьютера: **Win+Alt+R** (Xbox Game Bar, встроен в Windows) или бесплатный OBS Studio;
- экран телефона: встроенная запись экрана Android (шторка → «Запись экрана», включите звук устройства — будет слышна сирена аварийного);
- удобнее всего вывести телефон на компьютер программой **scrcpy** (бесплатно, через USB) и записать всё одним окном в OBS;
- монтаж: **Clipchamp** (встроен в Windows 11) или CapCut — склеить, ускорить ожидания, добавить подписи.

**Раскадровка на 3 минуты:**

| Время | Что в кадре | Подпись |
|---|---|---|
| 0:00–0:10 | вход, эмблема КМ | «НарядAI — наряд выдан, ИИ на контроле» |

## Обслуживание сервера

**Обновить сервер после правок в репозитории:**

```bash
cd /opt/naryadai && git pull && docker compose up -d --build
```

База при этом сохраняется. Миграции применяются сами при запуске.

**Перед каждым показом:** пульт `/demo` → **Сбросить сцену** (история за 3 месяца не трогается).

**Остановить / запустить:**

```bash
docker compose down
```

```bash
docker compose up -d
```

## Если что-то не работает

| Признак | Причина и что делать |
|---|---|
| Сайт не открывается, «не удаётся получить доступ» | домен не указывает на IP (`nslookup ВАШ_ДОМЕН`) или закрыты порты 80/443 (шаг 7.5 и файрвол в панели провайдера) |
| Ошибка сертификата / нет замка | Caddy не смог выпустить сертификат: порт 80 должен быть открыт, а `SITE_ADDRESS` — точно совпадать с доменом без `https://`. Смотрите `docker compose logs frontend` |
| 502 Bad Gateway | бэкенд не поднялся: `docker compose logs backend` — пришлите мне последние 50 строк |
| Сборка падает «killed» / нет памяти | у сервера меньше 4 ГБ — увеличьте тариф или добавьте swap: `fallocate -l 4G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile` |
| Бот молчит | `/api/health` показывает `"telegram":"off"` — проверьте токен в `.env`; затем `docker compose logs bot`. Пользователь должен нажать Start в боте через «Подключить Telegram» в профиле |
| ИИ в режиме «без ключа» | `ANTHROPIC_API_KEY` пустой или с пробелами; после правки `.env` — `docker compose up -d` |
| На телефоне нет камеры / микрофона | открыто не по HTTPS или запрещено в разрешениях сайта (замок в адресной строке → Разрешения) |
| Нет звука аварийного | телефон в беззвучном режиме или «Не беспокоить»; браузер разрешает звук после первого касания экрана — коснитесь приложения один раз после открытия |
| Не входит, «неверный ПИН» после 5 попыток | вход блокируется на время после 5 ошибок — подождите несколько минут |
| Данные испорчены во время репетиции | `make seed` — полный сброс базы (2–3 минуты) |

Любую ошибку присылайте с текстом или скриншотом и выводом `docker compose ps` — разберу.
